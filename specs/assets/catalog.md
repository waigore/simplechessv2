# Asset Catalog

Authoring rules: [`.agents/specs/rules/assets/catalog.md`](../../.agents/specs/rules/assets/catalog.md).

Catalog root and asset root: see **Catalog** in [`assets.md`](assets.md).

## Asset IDs

Every asset, whatever its source type or the skill that cataloged it, in demos and main code alike, has both:

- **Asset ID**: a lowercase UUID version 7, such as `0192f3a4-7c1e-7b2a-9d4e-5f6a7b8c9d0e`, generated by `python3 .github/scripts/new_asset_id.py`, never typed or copied. Never changed or reused, including on promotion. Code, catalog cross-references, and issues cite it.
- **Handle**: `<kind>/<name>`, a kind spec file name from the hub's Asset kinds table (written or planned), then a kebab-case name, such as `character-sprites/player-run`. The readable label for people and file paths. Unique across all entries, deprecated included: before assigning one, confirm it is unused in the catalog on `main` and in the catalog changes of every open PR. A handle may be renamed; the asset ID stays.

An update keeps the asset ID and raises the version. A replacement takes a new asset ID, and the old asset is deprecated with it as successor.

## Format

Default, unless the Integration ADR sets another: one entry file per asset, `<catalog-root>/<asset-id>.json`, holding one UTF-8 JSON object with the keys in [`catalog/fields.md`](catalog/fields.md). Omit keys that do not apply; no `null` values. Dates are `YYYY-MM-DD`. Only entry files live in the catalog root. An entry file stays after deprecation.

## Integrity

| ID | Rule | How checked |
|----|------|-------------|
| `I1` | Every file under the asset root, except engine import sidecars, belongs to one entry, and every entry's files exist | CI: `asset_catalog.py` |
| `I2` | Asset IDs are valid UUIDs version 7, unique, and never reused | CI: `asset_catalog.py` |
| `I3` | Every approved entry has a Pass review for its current version, or a review exemption | CI: `asset_catalog.py` |
| `I4` | Every cited ID exists; a planned kind spec named in the hub counts | CI for kind specs and successors; `review-asset` for the rest |
| `I5` | Main code uses no draft or deprecated asset | Code review + CI: main code cites only approved asset IDs from the generated manifest; no path/handle literals |
| `I6` | Every review exemption names the person who granted it | CI: `asset_catalog.py` |
| `I7` | Handles are unique, deprecated entries included, and prefixed by a kind spec the hub names | CI: `asset_catalog.py` |
| `I8` | No entry was generated or touched up with a tool that [`docs/asset-tools.md`](../../docs/asset-tools.md) bans | CI: `asset_catalog.py` |
| `I9` | Empty or omitted `coverage` on a non–person-supplied entry is allowed only when the asset ID is listed under Style anchors in its kind's `SS1` | CI: `asset_catalog.py` |
