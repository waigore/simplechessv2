# Authoring rules: aesthetics glossary

Read this before editing `specs/aesthetics/glossary.md` or a domain file split from it. Do not copy these rules into the spec.

Also read [aesthetics.md](aesthetics.md).

Shared language for aesthetics specs. Each term is defined once here. Other specs, including `specs/assets/` and `specs/ux/presentation.md`, use it exactly and link here.

Game terms stay in `specs/design/glossary.md`, view terms in `specs/view/glossary.md`, and UI terms in `specs/ux/glossary.md`. Asset pipeline terms stay in `specs/assets/glossary.md`. Do not redefine them here.

The skeleton already defines Art pixel, Medium, Palette set, Reference image, Reference sheet, Silhouette, Style pillar, and Swatch. Keep those rows. Add a row for a term this game needs. Keep added rows alphabetical. One term per concept: no synonyms.

Columns: term, a one-sentence definition, and where it is detailed (a link, or "here").

## Splitting

If the file passes 500 words, split added terms into `glossary/<domain>.md`. Keep `glossary.md` as the index, and update links.
