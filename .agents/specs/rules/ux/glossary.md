# Authoring rules: UX glossary

Read this before editing `specs/ux/glossary.md` or a domain file split from it. Do not copy these rules into the spec.

Also read [ux.md](ux.md).

Shared language for UX specs. Each term is defined once here. Other specs use it exactly and link here.

Game terms stay in `specs/design/glossary.md`. Do not redefine them here.

The skeleton already defines Actor, Binding, Control, Exception, Journey, Mockup, Mockup catalog, Region, Screen, and UI action. Keep those rows. Add a row for a term this game needs. Keep added rows alphabetical. One term per concept: no synonyms.

Columns: term, a one-sentence definition, and where it is detailed (a link, or "here").

## Splitting

If the file passes 500 words, split added terms into `glossary/<domain>.md`. Keep `glossary.md` as the index, and update links.
